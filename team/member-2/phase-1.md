3. Outline real namespaced EN/ES keys for navigation/loading/error/form actions. Each owner supplies their own feature keys. Ensure English/Spanish key parity and server dictionary assembly plan.

4. 5. Assemble the Phase1 three-page overview from all five contributions, finalize original wireframes/hotspots, and prepare MarvelApp/MockFlow assembly instructions. Record actual hosted prototype URL only after it exists and has been tested.

6. Collect Phase1 ERD/schema/prototype evidence for the MS Teams demo and check clean setup/build. Do not mark academic Phase1 complete while external prototype or team review is pending.

Run npm run check and npm run build, plus owned behavior/schema tests and visual review. Phase2 includes real backend validation tests as well as mock frontend interactions. Phase3 requires real Mongo/API tests; mocks do not count. Phase4 requires actual launch evidence. Run npm run check:ownership -- --member 2 --base development. Shared docs/config outside ownership go as exact handoff proposals to the owner.

## Handoff and stop

Update phase-1-evidence.md, handoff.md and status.json using real results. Set ready_for_review only when owned checks pass; only a reviewer records integrated after the actual PR merge. A blocked check remains blocked. Every PR needs visual review, passing unit tests and at least one peer approval. Stop before commit/push/merge/deploy unless the teammate explicitly asks. Never implement the next phase automatically.
