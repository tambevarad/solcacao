1. Summary

As in Phase 2, we used AI coding assistants as pair programmers. Four members used Claude Code (Anthropic) and one used Codex (OpenAI). The team set the plan and the turn order, chose the host, made every design decision and decided every review. Each member directed an assistant within their own files. The assistants drafted most of the code, tests and evidence text from those instructions and ran the checks. Every change was run and checked by its author, reviewed and approved by a second member, and passed CI against a real MongoDB before it was merged. We are responsible for all submitted work.

4. What stayed with people

  • The plan and turn order (D22), the hosting provider and its cost, and every secret: Varad generated the token secret and chose the inbox password on his own machine and entered them in Railway, which generates the database password itself. None was shown to an assistant or committed.
  • Every review decision and merge. Assistants ran the checks and summarized pull requests; the reviewer chose to approve or request changes.
  • Production sign-ins and anything outward-facing. The assistants' own safety checks blocked a production rollback and a direct database tunnel, which Varad handles in the Railway dashboard. Live journeys that sign in or read the password-protected inbox are run by Varad.

5. How we checked AI output

  • CI on every pull request: type checks, 595 unit, API and database tests against MongoDB with none skipped, live-API browser journeys with a Mailpit inbox, the mock checks and a production image build.
  • Each reviewer re-ran the checks before approving (Krish against a local MongoDB; Varad without one, relying on CI for the database tests) and checked the author's journey on the deployed site.
  • Evidence files record only commands that were actually run, with their real counts, and say plainly what was not run. Weekly records end with "Do not prefill a review, attendance, commit or success that did not occur."
  • When an assistant's first answer was wrong, the measurement decided. For example, the proxy setting suggested in #32 (1) was measured on the host and changed to 2, and an attempted fix for a browser warning that did not work was reverted and documented instead.
