2. Deliverables

Deliverable What we built Where
RESTful API using Node.js/Express Express 5 API with 18 endpoints for accounts, addresses, translations, products, carts, orders, business quotes with a PDF upload, and enquiries. One JSON envelope for success and errors, typed error codes, a JSON 404 for unknown paths, strict request validation (zod), a 100 kB body limit, CORS allowlist, Helmet security headers and per-client rate limits. server/src, docs/api.json
Database integration MongoDB through Mongoose: User, CorporatePartner, Address, Product, Inventory, Cart, Order, B2bRequest and Inquiry. Unique and query indexes are built at startup; the catalog indexes were added after measuring the queries. A seed script loads the fictional catalog. server/src/features/*/model*.ts, server/src/shared/db.ts, docs/data-model.md
Server-side business logic Password hashing (bcrypt) and signed one-hour tokens with roles re-read from the database; cart merge on sign-in capped by stock and safe to retry; order totals computed on the server from database prices (the browser never sends a price); business quotes stored privately with owner-only file download; enquiries with server-side product snapshots; email notifications that report "saved" separately from "sent". server/src/features/{auth,catalog,b2b,support}, server/src/shared
Front-end connected to the API using fetch() One shared fetch() client adds the sign-in token and turns the API's error envelope into one typed error. Each feature has an HTTP adapter behind the same interface as its Phase 2 mock, chosen by VITE_API_MODE=http. Failures show an error state; nothing falls back to mock data. client/src/api/http.ts, client/src/features/*/http.ts
AI Usage Log Tools, who used them, for what, and what the team decided and verified ai-usage-log.pdf

3. Testing

Continuous integration runs on every pull request: type checks and 595 unit, API and database tests against a real MongoDB with none skipped; 6 cross-feature browser journeys against the live API with MongoDB and a Mailpit inbox (catalog, guest order, cart merge on sign-in, contact email, business quote with a PDF, six-piece sampler) plus 11 catalog journeys; the Phase 2 mock checks; and a production image build. Each member also ran their journeys against the deployed site (their phase-3-evidence.md and phase-4-evidence.md).
